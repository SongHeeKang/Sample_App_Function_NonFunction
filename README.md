# 앱 기능·비기능 검증 (App Functional / Non-Functional Testing)

모바일 콘텐츠 마켓 앱(게임·앱·영화·방송·eBook·만화·음악·쇼핑 등 13개 카테고리)을 대상으로
**기능 검증**(요구사항 기반 TC 설계·수행, 자사/타사 단말 교차 검증, 업데이트 검증)과
**비기능 검증**(E2E 응답 시간, 소모 전류)을 진행한 내용을 정리한 자료입니다.

> 보안 안내: 실무 자료이므로 회사·서비스 식별 정보와 내부 정보는 마스킹했습니다.
> 마스킹 항목은 [보안 처리 내역](#보안-처리-내역)에 정리되어 있습니다.

## 1. 기능 검증

### 1-1. 시나리오 분석 → 테스트 설계

기획서의 프로세스 흐름도를 바탕으로 분기 조건마다 정상/예외 케이스를 뽑아 TC를 설계했습니다.
아래는 **MDN(휴대폰 번호) 인증 프로세스** 예시입니다.

<img width="615" height="416" alt="MDN 인증 시나리오" src="https://github.com/user-attachments/assets/5e2d805b-eaf7-4fc9-a189-d59c30a16b73" />

- 캡차 미입력 → 팝업 "캡차인증 미입력"
- 캡차 인증 실패 → 팝업 "캡차인증 실패"
- 캡차 인증 성공 → SMS 인증번호 발송 (문구·발신번호 검증 포함)
- 인증번호 유효시간 **3분 이내/초과**에 따른 분기 검증

분기마다 최소 1개의 TC가 대응되도록 해서 흐름 누락이 없게 했습니다.

### 1-2. 테스트 케이스 (TC)

<img width="1403" height="526" alt="Test Case" src="https://github.com/user-attachments/assets/eab4d9fe-43ae-42fb-a1f7-54d09e2466ba" />

TC 하나에 아래 항목을 관리해 **요구사항과 결과를 추적**할 수 있게 했습니다.

| 항목 | 설명 |
| --- | --- |
| 요구사항 ID | 기획서/운영 요구사항 번호 (예: `REQ211_03_9.1`) |
| 테스트케이스 ID | 카테고리 접두어 + 일련번호 (예: `SHP-03130` 쇼핑, `MYP-03180` 마이페이지) |
| 카테고리 / 중요도 | 기능 영역, 우선순위(상/중/하) |
| 사전조건 · 절차 · 예상 결과 | 재현 가능한 단계별 절차와 기대 동작 |
| 실제 결과 | Fail이면 이슈 번호와 현상을 기록 |
| 자사 / 타사 | 단말별 P / F 결과 |

**이슈 예시** — 쇼핑 > 배송상품 > 배송지 입력 화면 진입 시, 특정 단말(GB)에서
'인증서 사용불가' 팝업이 뜨는 결함을 찾아 이슈로 등록했습니다(자사·타사 단말 모두 재현).

## 2. 비기능 검증

### 2-1. E2E 응답 시간 (앱 실행 속도)

<img width="1278" height="699" alt="E2E Response Time" src="https://github.com/user-attachments/assets/facc407d-2d79-407e-8ac7-8850a3fa1d01" />

- **도구**: QVIC — Memory Leak / E2E Response Time / App Traffic / Battery Consumption 중 *E2E Response Time* 선택
- **방법**: 단말을 연결한 뒤 테스트 시나리오(앱 실행)를 반복 수행해 `앱 실행 → 앱 실행 확인`까지 걸린 시간을 측정
- **결과**: 평균 **2.11초**, 90th percentile **2.17초**
  - 26회 측정 대부분이 1.85~2.41초 범위에 들었고, 튀는 값(3.06초)은 1회였습니다.
  - 평균만 보지 않고 90th percentile도 함께 기록해 **체감 성능의 편차**까지 확인했습니다.

### 2-2. 소모 전류 (배터리)

<img width="1278" height="699" alt="Current Consumption" src="https://github.com/user-attachments/assets/dbde6c02-a16b-480a-ab18-b16dc75011f3" />

- **도구**: Smart Power Scope(실시간 전류 파형), Auto Power Scope(시나리오 반복 자동 측정)
- **방법**: 같은 시나리오를 여러 회차(7회) 반복 측정하고, 결과를 Excel Summary로 정리
  - 회차별 **총 전류 소모량 평균**
  - **로그캣(logcat) / 덤프시스(dumpsys)** 구간별 평균 및 최대값
  - 회차별 추이 그래프로 이상 구간(피크) 확인
- **결과**: 총 전류 소모량은 회차마다 평균 약 **17~23 mA**로 안정적이었습니다. 로그캣·덤프시스 구간에서는 회차별 편차가 커서 구간별 원인을 분석했습니다.

## 3. 수행 프로세스

```
요구사항/기획서 분석
      ↓
시나리오(프로세스 흐름) 분석 → 분기별 테스트 포인트 도출
      ↓
TC 설계 (요구사항 ID ↔ TC ID 매핑, 중요도 부여)
      ↓
기능 검증 수행 (자사/타사 단말 교차) → 결함 등록·재검증
      ↓
업데이트 검증 (통신사별·자급제 단말)
      ↓
비기능 검증 (E2E 응답 시간, 소모 전류)
      ↓
결과 Summary 리포트 (카테고리별 수행률/Pass율/진행률)
```

## 4. 핵심 역량

- **요구사항 기반 테스트 설계**: 흐름도 분기를 TC로 옮기고, 요구사항 ID로 추적
- **멀티 단말·통신사 교차 검증**: 자사/타사, 통신사별·자급제 단말 환경 차이 확인
- **정량적 비기능 측정**: 툴로 응답 시간·전류를 측정하고 평균/백분위/최대값 기준으로 판단
- **결과 리포팅**: 카테고리별 수행률·Pass율·잔여 TC로 진행 상황을 한눈에 보여주는 Summary 작성
